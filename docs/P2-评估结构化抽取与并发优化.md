# P2：评估、结构化抽取与并发优化

## 目标

P2 解决三个问题：量化筛选质量、把可申报通知转换为可直接使用的结构化信息、在不牺牲可靠性的前提下缩短 AI 筛选耗时。并发基准结论适用于当时使用的模型与运行环境，不改变当前 Agnes 主用、Ollama fallback 的 provider 配置。

实施顺序固定为：评估基线 → 结构化抽取 → 并发基准测试。并发参数只有在同一批样本上通过质量与稳定性门槛后才允许提高。

## 人工标注与指标

### 主口径：事件时点评估

- 人工结论回答“若系统在文章发布当日抓到这条记录，是否应推送”。旧的 `2026-07-07` 快照审核仅保留作可行动性审计，不能作为筛选质量主指标。
- `event_date` 优先使用页面 `publish_date`；缺失时可使用系统 `first_seen_at` 作为代理时点，并明确标记 `event_time_basis=first_seen_at`；两者均不可用时标记 `unknown`，不参与主指标。
- 标记“是”必须同时满足：规划/建设行业相关、内容为申报/征集/参评/竞赛报名机会、且在 `event_date` 当天仍可行动。
- 获奖结果、名单公示、评审结果、颁奖回顾一律标记“否”，不属于应推送信息；培训、会议、招聘和非行业内容同样标记“否”。
- 事件时点评估表必须保留 `内容类型`、`行业相关`、`事件时点可行动`、证据链接和说明，以及旧快照口径的结论与备注，禁止覆盖原审核文件。

### 抽样与统计

- 旧版状态映射：`ai_confirmed/pushed` 为预测正例，`ai_rejected/new` 为预测负例；旧版 `new` 已通过运行日志核对为未进入 AI 的关键词负例。
- 完整清单导出全部历史记录；优先标注队列包含全部 AI 阶段记录，以及按来源分层抽取的 120 条关键词负例。
- 空白、“不确定”和 `event_time_basis=unknown` 不参与指标计算。报告必须分别显示明确标注、不确定、时点不可判定和待标注数量及权重，避免把部分标注误写成完整基线。
- 分层样本使用 `总体数/样本数` 权重，输出加权混淆矩阵、准确率、精确率、召回率、F1，以及确定性分层 bootstrap 95% 区间。

## schema v3

保留 `articles` 主表，新增一对一的 `article_extractions`：

| 字段 | 含义 |
|------|------|
| `article_id` | 对应文章，主键及外键 |
| `is_award_application` | 本次结构化判断 |
| `award_name` | 奖项名称 |
| `deadline_text` | 截止日期原文 |
| `deadline_date` | 能确定时写入 `YYYY-MM-DD` |
| `applicant_scope` | JSON 数组形式的申报对象 |
| `model` | 实际使用的 AI 模型（当前主用 Agnes，fallback 为 Ollama） |
| `prompt_version` | 提示词版本 |
| `raw_response` | AI 原始响应，供审计 |
| `created_at/updated_at` | 创建和更新时间 |

迁移只创建新表，不自动回填缺少正文的历史记录。生产库迁移前必须备份，并先在数据库副本上验证 `PRAGMA integrity_check`、文章总数和 schema 版本。

## AI 响应契约

分类与抽取合并为一次请求。提示词必须提供判断日期和发布日期；已过截止日期或奖项年份明显过期时返回否。`applicant_scope` 不得包含 `null`，未知时返回空数组。AI 只允许返回 JSON：

```json
{
  "is_award_application": true,
  "reason": "仍在申报期",
  "award_name": "奖项名称或 null",
  "deadline_text": "原文日期或 null",
  "deadline_date": "2026-08-01 或 null",
  "applicant_scope": ["申报对象一", "申报对象二"]
}
```

布尔类型、日期格式或申报对象类型不合法时保持 `ai_pending`，不得猜测或推送。判定为否时允许结构化字段为空。

## 并发与熔断

- `filter.ai.max_workers` 范围为 1～4，默认 1。
- 并发实现必须保持输入顺序和有限在途请求；出现传输故障后停止提交新请求，最多等待已经在途的请求结束。
- 使用相同模型和固定样本测试 1、2、4 workers。
- 只有相对单线程吞吐提升至少 30%、判断一致、且无新增无效响应或传输错误时才提高生产参数；多个并发数达标时选择最小值，减少故障时的在途请求，否则保持 1。

## 验收

- 自动化测试不访问真实飞书 Webhook。
- 测试覆盖：评估抽样与权重、指标计算、schema v2→v3、结构化 JSON 严格解析、抽取结果持久化、通知展示、并发顺序和熔断。
- 临时数据库迁移演练通过后才迁移生产库。
- 正常渠道验证使用 `--dry-run`；生产数据库不因 dry-run 改变。
